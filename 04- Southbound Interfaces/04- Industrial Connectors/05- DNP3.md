AnyLog can act as a **DNP3 master** over **TCP** or **TLS** (using **hostname** and **port**, default **20000**). 
Data is read on a schedule and streamed into your local operator database as JSON, using the same `**run plc client**` 
pattern as [Modbus](02-%20Modbus.md), [OPC-UA](03-%20OPC-UA.md#continuous-data-pull), and [EtherNet/IP](04-%20EtherIP.md#the-run-plc-client-command).

For a production-style deployment of a DNP3 connection from a standing script (rather than one-off CLI commands), see 
[Deploying a DNP3 Connector via Script](./05-1%20DNP3/01-%20DNP3%20-%20Deploying%20Connector%20via%20Script.md). For 
reusing a single point map across multiple outstations instead of repeating it inline, see [DNP3 Mapping Policies](05-1%20DNP3/02-%20DNP3%20-%20Mapping-Policies.md).

| Requirement               | Notes                                                |
| ------------------------- | ---------------------------------------------------- |
| `**opendnp3**` (yadnp3)** | Must be installed in the AnyLog runtime environment. |

Declare the target DBMS before streaming, for example:

```anylog
connect dbms new_company where type = sqlite
```

## Connection and map

DNP3 uses `**hostname**` and `**port**`. `**master_id**` and `**outstation_id**` are the DNP3 link addresses (defaults: master **1**, outstation **10**).

`**map**` is a **JSON array** of points. Each object must include:

| Key | Required | Meaning |
|---|---|---|
| `name` | yes | Column / logical label |
| `index` | yes | Point index on the outstation |
| `type` | one of `type` or `group`+`variation` | Point class (see table below) |
| `group`, `variation` | alternative to `type` | Raw DNP3 group/variation |

Supported `**type**` values (case-insensitive; spaces/underscores ignored):

| `type` | DNP3 group / variation |
|---|---|
| `Analog` | 30 / 6 |
| `Binary` | 1 / 2 |
| `BinaryOutputStatus` | 10 / 2 |
| `AnalogOutputStatus` or `AnalogOutput` | 40 / 4 |
| `Counter` | 20 / 6 |
| `DoubleBit` or `DoubleBitBinary` | 3 / 2 |

`map` can be written inline, as shown throughout this page, or declared once as a reusable policy on the
blockchain and referenced across multiple connections — see [DNP3 Mapping Policies](05-1%20DNP3/02-%20DNP3%20-%20Mapping-Policies.md).

Optional **TLS** (all three PEM paths required when `enable_tls = true`):

| Keyword | Meaning |
|---|---|
| `enable_tls` | Use TLS instead of plain TCP |
| `tls_ca` | CA certificate (PEM file path) |
| `tls_cert` | Client certificate (PEM file path) |
| `tls_key` | Client private key (PEM file path) |

---

In AnyLog, we use a map (a JSON array of points). Each point has a `**name**` (the column name), an `**index**` (the point index on the outstation) and a `**type**` (the DNP3 point class), or `**group**` and `**variation**` instead of `type`.

```json
[
  {"name":"voltage_l1","type":"Analog","index":0},
  {"name":"current_l1","type":"Analog","index":1},
  {"name":"active_power_kw","type":"Analog","index":6},
  {"name":"breaker_closed","type":"Binary","index":0},
  {"name":"energy_kwh","type":"Counter","index":0}
]
```

## One-shot read

```anylog
<get plc values where type = dnp3 and
    hostname = 127.0.0.1 and
    port = 20000 and
    master_id = 1 and
    outstation_id = 10 and

           {"name":"current_l1","type":"Analog","index":1},
           {"name":"active_power_kw","type":"Analog","index":6},
```

## Constant columns (`value`)

A map item with a `value` and no point is not read from the outstation. Its `name` becomes a column, and the same value is copied onto every row:

```json
{"name":"station_id","value":"WST_1"}
```

Use a constant for something the outstation does not report but every row should carry, such as a station id, a model, a serial number, or a manufacturer. The value can be a string, a number, or a boolean.

```anylog
<get plc values where type = dnp3 and
    hostname = 127.0.0.1 and
    port = 20000 and
    master_id = 1 and
    outstation_id = 10 and
    map = [{"name":"voltage_l1","type":"Analog","index":0},
           {"name":"current_l1","type":"Analog","index":1},
           {"name":"active_power_kw","type":"Analog","index":6},
           {"name":"breaker_closed","type":"Binary","index":0},
           {"name":"energy_kwh","type":"Counter","index":0},
           {"name":"station_id","value":"WST_1"}]
>
```

Output:

```
DNP3 values
Column          Tag      Value  Error Note        
---------------|--------|------|-----|-----------|
voltage_l1     |g30v6:i0|231.02|     |           |
current_l1     |g30v6:i1|  49.3|     |           |
active_power_kw|g30v6:i6|11.326|     |           |
breaker_closed |g1v2:i0 |     0|     |           |
energy_kwh     |g20v6:i0| 48211|     |           |
station_id     |       -|WST_1 |     |constant   |
```

Rules:

* A constant item has `name` and `value` only. Do not combine `value` with `type` or `index` on the same item.
* A map needs at least one point. A map that contains only constants is rejected.
* The `name` must be unique in the map. A duplicate name is rejected.
* In a `run plc client` command, constants are copied onto each stored row of the wide table and of the UNS path.

## Reading without storing (`emit`)

By default every point in `map` is stored. Set `"emit": false` on a point to read it without storing it:

```json
{"name":"breaker_status","type":"BinaryOutputStatus","index":0,"emit":false}
```

With `emit: false`, the point is still read on every poll and its value is shown by `get plc values`, but it is not written to the table, and it does not get a UNS object or a policy column.

Use it for a value you want to see on the command line during testing, but do not want in the database, such as a status point that another point depends on.

```anylog
<get plc values where type = dnp3 and
    hostname = 127.0.0.1 and
    port = 20000 and
    master_id = 1 and
    outstation_id = 10 and
    map = [{"name":"voltage_l1","type":"Analog","index":0},
           {"name":"current_l1","type":"Analog","index":1},
           {"name":"active_power_kw","type":"Analog","index":6},
           {"name":"breaker_closed","type":"Binary","index":0},
           {"name":"energy_kwh","type":"Counter","index":0},
           {"name":"station_id","value":"WST_1"},
           {"name":"breaker_status","type":"BinaryOutputStatus","index":0,"emit":false}]
>
```

Output:

```
DNP3 values
Column          Tag      Value  Error Note        
---------------|--------|------|-----|-----------|
voltage_l1     |g30v6:i0|231.02|     |           |
current_l1     |g30v6:i1|  49.3|     |           |
active_power_kw|g30v6:i6|11.326|     |           |
```

## Continuous ingest — wide table

With `**table = ...**` and `**dbms**`, all points from `**map**` land in **one table**. Each poll inserts **one row**; every object in `**map`** is **one column**: the map `**name`** is the **column name**, and that column stores the value read for that point.

```anylog
<run plc client where type = dnp3 and
    hostname = 127.0.0.1 and
    port = 20001 and
    master_id = 1 and
    outstation_id = 10 and
    frequency = 20 and
    name = dnp3_rtu and
    dbms = new_company and
    table = dnp3_substations and
    map = [{"name":"voltage_l1","type":"Analog","index":0},
           {"name":"current_l1","type":"Analog","index":1},
           {"name":"active_power_kw","type":"Analog","index":6},
           {"name":"breaker_closed","type":"Binary","index":0},
           {"name":"energy_kwh","type":"Counter","index":0},
           {"name":"station_id","value":"WST_1"}]
>
```

The constant `station_id` is a column on the same table, copied onto every row:

Tables:

* `dnp3_substations`

```
Schema for DBMS: 'new_company' and Table: 'dnp3_substations'
Column Name       Column Type
-----------------|---------------------------|
row_id           |integer                    |
insert_timestamp |timestamp without time zone|
tsd_name         |char(3)                    |
tsd_id           |int                        |
timestamp        |timestamp without time zone|
duration         |int                        |
voltage_l1       |decimal                    |
current_l1       |decimal                    |
active_power_kw  |decimal                    |
breaker_closed   |int                        |
energy_kwh       |int                        |
station_id       |char(5)                    |
```

## Continuous ingest — one table per point (`table_per_value = true`)

Set `**table_per_value = true**` and omit `**table**`. Each object in `**map**` is written to its **own table**. The table name is the client `**name`** plus the map `**name`** (for example `**dnp3_dyn_voltage_l1**`). Each row includes `**timestamp**`, `**tag**`, and `**value**`.

```anylog
<run plc client where type = dnp3 and
    hostname = 127.0.0.1 and
    port = 20001 and
    master_id = 1 and
    outstation_id = 10 and
    frequency = 20 and
    name = dnp3_dyn and
    dbms = new_company and
    table_per_value = true and
    auto_uns = false and
    map = [{"name":"voltage_l1","type":"Analog","index":0},
           {"name":"current_l1","type":"Analog","index":1},
           {"name":"active_power_kw","type":"Analog","index":6},
           {"name":"breaker_closed","type":"Binary","index":0},
           {"name":"energy_kwh","type":"Counter","index":0},
           {"name":"station_id","value":"WST_1"}]
>
```

Tables:

* `dnp3_dyn_voltage_l1`
* `dnp3_dyn_current_l1`
* `dnp3_dyn_active_power_kw`
* `dnp3_dyn_breaker_closed`
* `dnp3_dyn_energy_kwh`

**Constants are not stored in per-value tables.** In the map above, `station_id` is a constant. With `table_per_value` (and no UNS), it does not create a table, and it is not added as a column on any per-value table. Each per-value table has only `tag` and `value`, as shown below. Constants are only copied onto fixed (wide) tables.

Example columns for `dnp3_dyn_voltage_l1` (the other tables use the same layout):

```
Schema for DBMS: 'new_company' and Table: 'dnp3_dyn_voltage_l1'
Column Name      Column Type
----------------|---------------------------|
row_id          |integer                    |
insert_timestamp|timestamp without time zone|
tsd_name        |char(3)                    |
tsd_id          |int                        |
timestamp       |timestamp without time zone|
tag             |char(10)                   |
value           |decimal                    |
```

## Ingest with UNS and`namespace` set

With `**table_per_value = true**`, `**auto_uns = true**`, and `**master_node**`, each point is registered in the UNS.   

`**The proivided namespace**` sets the path and requires `**master_node = [ip:port]**`.

```anylog
<run plc client where type = dnp3 and
    hostname = 127.0.0.1 and
    port = 20001 and
    master_id = 1 and
    outstation_id = 10 and
    frequency = 20 and
    name = dnp3_uns and
    dbms = new_company and
    table_per_value = true and
    auto_uns = true and
    master_node = 192.168.1.88:32048 and
    namespace = FA9/MID9/DEVICE9 and
    map = [{"name":"voltage_l1","type":"Analog","index":0},
           {"name":"current_l1","type":"Analog","index":1},
           {"name":"active_power_kw","type":"Analog","index":6},
           {"name":"breaker_closed","type":"Binary","index":0},
           {"name":"energy_kwh","type":"Counter","index":0},
           {"name":"station_id","value":"WST_1"}]
>
```

Tables (the trailing `_1` is from the UNS mapping):

* `dnp3_uns_voltage_l1_1`
* `dnp3_uns_current_l1_1`
* `dnp3_uns_active_power_kw_1`
* `dnp3_uns_breaker_closed_1`
* `dnp3_uns_energy_kwh_1`

**Constants are not stored in per-value tables.** `station_id` does not create a table or a column here. Only the point values are stored.

Example columns for `dnp3_uns_voltage_l1_1` (the value column is named for that map point; the other tables use the same layout):

## Command-line `constants` and `group_by_attributes`

On `run plc client`, you can specify constants on the **command line** (`constants = {...}`) and/or in the **map** (`{"name":...,"value":...}`). Either way, each constant is a **column** in a fixed (wide) table and is copied onto the fixed-table UNS objects. Per-value tables do not carry constants.

* `constants = {"station_id":"WS-001",...}` copies those keys onto **every stored row** of a fixed table. A command-line constant **replaces** a map `{"name":...,"value":...}` entry with the same name.
* `group_by_attributes = [station_id]` stores those attribute values on each fixed-table UNS **object** as a `where` clause (for example `station_id = 'WS-001'`).  
Names in the list must match keys from `constants` or the map.

Example object for station **WS-001** (`pressure_hpa` on the `outstations_dnp3` use case below). The `where` key comes from `group_by_attributes`:

```json
{
  "object": {
    "station_id": "WS-001",
    "device": "dnp3-dev1",
    "model": "DX1234D1",
    "name": "pressure_hpa",
    "column": "pressure_hpa",
    "dnp3": {
      "index": 0,
      "type": "Analog"
    },
    "dbms": "env_sensor",
    "table": "outstations_dnp3",
    "where": "station_id = 'WS-001'"
  }
}
```

See the use case below for a full example.

## DNP3 Out Station Testing

The [opendnp3](https://github.com/dnp3/opendnp3) library includes a demo outstation for lab tests. Build it with demos enabled (TLS optional):

```bash
git clone --recursive -b release-2.x https://github.com/dnp3/opendnp3.git
cd opendnp3
mkdir build && cd build
cmake -DDNP3_DEMO=ON -DDNP3_TLS=ON ..    # omit -DDNP3_TLS=ON for TCP-only
make -j
```

See the [OpenDNP3 CMake guide](https://dnp3.github.io/docs/guide/3.0.0/build/cmake/) and [TLS support](https://dnp3.github.io/docs/guide/3.0.0/api/tls/) (OpenSSL ≥ 1.1.1 required for TLS).

### Plain TCP outstation

From the opendnp3 build directory:

```bash
cd ~/opendnp3/build
./outstation-demo
```

The demo listens on **any IP address**, port **20001**, outstation link id **10**, and expects master link id **1**. Use those values in AnyLog:

```anylog
<get dnp3 values where type = dnp3 and
    hostname = 127.0.0.1 and
    port = 20001 and
    master_id = 1 and
    outstation_id = 10 and
    map = [{"name":"analog_0","type":"Analog","index":0},
           {"name":"binary_0","type":"Binary","index":0},
           {"name":"counter_0","type":"Counter","index":0},
           {"name":"doublebit_0","type":"DoubleBit","index":0}]
>
```

Once started, the demo logs traffic and waits for input to send unsolicited measurement changes:

```text
Enter one or more measurement changes then press <enter>
c = counter, b = binary, d = doublebit, a = analog, o = octet string, 'quit' = exit
```

### TLS outstation

Generate a test CA chain first — see [DNP3 TLS Test Certificates](05-1%20DNP3/03-%20DNP3%20-%20TLS%20test%20certificates.md) for the full script and instructions. Run it in a working directory of your own, outside this repository:

```bash
mkdir -p ~/dnp3-tls-test && cd ~/dnp3-tls-test
bash create_certificates.sh
```

| Side | CA (peer) | Certificate | Private key |
|------|-----------|-------------|-------------|
| AnyLog master | `anylogDNP3ca.cert` | `master1.cert` | `master1.key` |
| Outstation | `anylogDNP3ca.cert` | `outstation1.cert` | `outstation1.key` |

From the opendnp3 build directory, start the TLS demo with three PEM paths (CA, outstation certificate, outstation private key):

```bash
cd ~/opendnp3/build
./outstation-tls-demo \
  ~/dnp3-tls-test/anylogDNP3ca.cert \
  ~/dnp3-tls-test/outstation1.cert \
  ~/dnp3-tls-test/outstation1.key
```

Same link ids and port as plain TCP (**master_id = 1**, **outstation_id = 10**, port **20001**). AnyLog master uses the **master** certificate files from the same CA chain.

Example AnyLog one-shot read:

```anylog
<get dnp3 values where type = dnp3 and
    hostname = 127.0.0.1 and
    port = 20001 and
    master_id = 1 and
    outstation_id = 10 and
    enable_tls = true and
    tls_ca = ~/dnp3-tls-test/anylogDNP3ca.cert and
    tls_cert = ~/dnp3-tls-test/master1.cert and
    tls_key = ~/dnp3-tls-test/master1.key and
    map = [{"name":"voltage_l1","type":"Analog","index":0},
           {"name":"current_l1","type":"Analog","index":1},
           {"name":"active_power_kw","type":"Analog","index":6},
           {"name":"breaker_closed","type":"Binary","index":0},
           {"name":"energy_kwh","type":"Counter","index":0}]
>
```

More detail, including the full generation script: [DNP3 TLS Test Certificates](05-1%20DNP3/03-%20DNP3%20-%20TLS%20test%20certificates.md).

## Use case with multiple outstations with multiple operators

Each operator node runs **one** `run plc client` for its outstation — same map and shared table `outstations_dnp3`, different host, client `**name`**, and `**constants`** (here `station_id` WS-001 vs WS-002). Set `**auto_uns = true**` so the table is registered and the other nodes can see it. `**group_by_attributes = [station_id]**` stores each station's value on its UNS objects as a `where` clause, so the objects are scoped by station.

**The map and the constant names must be the same on every operator.** All operators that write to `outstations_dnp3` must use the identical `**map`** (same `name` values, `type` and `index`) and the same constant keys (`device`, `model`, `station_id`). Otherwise the rows do not match the table schema. Only the values change from one operator to the next: `**hostname`**, client `**name**`, and the constant values (`station_id`, `device`, `model`).

Note: The table `outstations_dnp3` is virtual and its information stays in the ledger once created, so the first node that runs the command creates the table and its metadata, and every other operator node sees that it exists and writes its data into it, as long as it uses the same `dbms`, `table`, and `map`.

**Operator 1 — station WS-001**

```anylog
<run plc client where type = dnp3 and
    name = dnp3-1 and
    hostname = 127.0.0.1 and
    port = 20001 and
    master_id = 1 and
    outstation_id = 10 and
    frequency = 10 and
    dbms = env_sensor and
    table = outstations_dnp3 and
    auto_uns = true and
    constants = {"device":"dnp3-dev1","model":"DX1234D1","station_id":"WS-001"} and
    group_by_attributes = [station_id] and
    map = [{"name":"pressure_hpa","type":"Analog","index":0},
           {"name":"temperature_f","type":"Analog","index":1},
           {"name":"relative_humidity_pct","type":"Analog","index":2},
           {"name":"wind_speed_ms","type":"Analog","index":3},
           {"name":"wind_direction_deg","type":"Analog","index":4}]
>
```

**Operator 2 — station WS-002**

```anylog
<run plc client where type = dnp3 and
    name = dnp3-2 and
    hostname = 127.0.0.2 and
    port = 20001 and
    master_id = 1 and
    outstation_id = 10 and
    frequency = 10 and
    dbms = env_sensor and
    table = outstations_dnp3 and
    auto_uns = true and
    constants = {"device":"dnp3-dev2","model":"DX1234D9","station_id":"WS-002"} and
    group_by_attributes = [station_id] and
    map = [{"name":"pressure_hpa","type":"Analog","index":0},
           {"name":"temperature_f","type":"Analog","index":1},
           {"name":"relative_humidity_pct","type":"Analog","index":2},
           {"name":"wind_speed_ms","type":"Analog","index":3},
           {"name":"wind_direction_deg","type":"Analog","index":4}]
>
```

Both operators write to the same table. Rows are distinguished by `station_id` (and the other constants).

Tables:

* `outstations_dnp3`

Schema for DBMS: `env_sensor` and Table: `outstations_dnp3`. The table has the five point columns plus `device`, `model`, and `station_id`:

