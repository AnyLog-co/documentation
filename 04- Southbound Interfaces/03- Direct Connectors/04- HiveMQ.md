# HiveMQ 

HiveMQ helps industrial organizations move faster and operate smarter by turning industrial data into real-time 
intelligence and autonomous action at the edge.

* <a href="https://docs.hivemq.com/hivemq/latest/user-guide/" target="_blank">HiveMQ Documentation</a>
* <a href="https://hub.docker.com/u/hivemq" target="_blank">HiveMQ Docker</a>

There are two ways to get data from HiveMQ into AnyLog:

| Option | Data flow | Requires |
|---|---|---|
| **A. AnyLog subscribes to HiveMQ** | Publisher → HiveMQ → `run msg client` (broker = HiveMQ IP) | Nothing extra – simplest |
| **B. HiveMQ forwards to AnyLog** | Publisher → HiveMQ → (Bridge / Kafka extension) → AnyLog local broker or Kafka → `run msg client` / `run kafka consumer` | HiveMQ Enterprise Bridge or Kafka extension (trial mode in the `hivemq4` image) |

Option A is recommended for testing. Option B is useful when AnyLog should be the endpoint that HiveMQ pushes to 
(e.g. AnyLog's broker is reachable but HiveMQ is behind a firewall).

## Deploying HiveMQ 

HiveMQ's <a href="https://docs.hivemq.com/hivemq/latest/user-guide/getting-started.html" target="_blank">Getting Started guide</a> runs the 
broker with a free 30-day **Lab license** (non-production; enterprise extensions such as Bridge and Kafka run without 
the trial time limit) and provides a simulated-telemetry script. 

1. Create a free account – go to <a href="https://www.hivemq.com/" target="_blank">hivemq.com</a> → **Try HiveMQ** and sign up. The account 
   opens in the HiveMQ Platform (<a href="https://app.hivemq.com" target="_blank">app.hivemq.com</a>).

2. On the welcome screen, select **Download HiveMQ Software** → **Continue** → **Docker**. A Lab license key is 
   generated automatically.

3. Copy the command under **Run the container** and run it in a terminal. The command already contains the license 
   key as an environment variable; it is equivalent to:

```shell
docker run -d \
  -p 8080:8080 \
  -p 1883:1883 \
  -e <LICENSE ENV VAR FROM PLATFORM>=<KEY> \
  --name hivemq \
  hivemq/hivemq4:latest
```

* `1883` – MQTT listener (publishers and AnyLog connect here)
* `8080` – HiveMQ Control Center

4. Click **View broker** in the platform – a *Broker connected!* notice confirms the broker registered.

> **Without an account:** the same `docker run` without the license variable starts HiveMQ in trial mode, and 
> `hivemq/hivemq-ce` is the fully open-source option (MQTT only, no Control Center or enterprise extensions). 
> In both cases use the [Python publisher](#alternative--python-publisher) below for data.

5. Goto Website: http://localhost:8080/ (**username**: admin | **password**: hivemq)

6. Validate the broker is accepting connections using the HiveMQ MQTT CLI – subscribe in one terminal: 

```shell
docker run --rm -it --network host hivemq/mqtt-cli \
  sub -h localhost -p 1883 -t 'sensors/#' -T
```

and publish a test message from a second terminal:

```shell
docker run --rm --network host hivemq/mqtt-cli \
  pub -h localhost -p 1883 -t sensors/test -m '{"timestamp": "2026-10-22T10:00:00Z", "value": 1.0}'
```

The message should appear in the subscriber, and the client should show up under **Clients** in the Control Center.

> On macOS / Windows Docker Desktop, `--network host` may not behave as expected – replace `localhost` with 
> `host.docker.internal`.

## Publishing Data

### HiveMQ Simulated Telemetry

HiveMQ provides a Bash script that publishes simulated device data (machine states, throughput values, etc.) using 
the HiveMQ MQTT CLI, which is bundled with the HiveMQ software. 

1. In the HiveMQ Platform, after the broker connects, select **Next, get data flowing**.
2. On the **Get data flowing** page select **Use simulated data** → **Docker** tab.
3. Copy the script and run it in a new terminal. Leave it running – after about a minute a *Data is flowing!* 
   notice confirms data reaches the broker.

The script is generated by the platform, so the topic structure and payload are not published in the docs. Before 
writing the AnyLog policy, subscribe to everything and capture a few messages:

```shell
docker run --rm -it --network host hivemq/mqtt-cli \
  sub -h localhost -p 1883 -t '#' -T
```

From the output, note:
* **Topic(s)** – used as `name` in `run msg client` (wildcards such as `factory/#` are supported).
* **Payload keys** – each key used in a `bring [key]` mapping. 
* **Timestamp format** – if the payload has no timestamp, use `column.timestamp.timestamp = now()`.

### Alternative – Python Publisher

For setups without a HiveMQ account (trial mode / CE), the script below publishes a random sensor reading every 
few seconds. Each message is a JSON object with the device name, a timestamp and a value. 

```python
# hivemq_publisher.py   ->   pip install paho-mqtt
import json, random, time
from datetime import datetime, timezone
import paho.mqtt.client as mqtt

BROKER = "localhost"      # HiveMQ host
PORT = 1883
TOPIC = "sensors/data"
DEVICES = ["sensor-1", "sensor-2", "sensor-3"]

client = mqtt.Client(mqtt.CallbackAPIVersion.VERSION2, client_id="anylog-demo-publisher")
client.connect(BROKER, PORT)
client.loop_start()

try:
    while True:
        for device in DEVICES:
            payload = {
                "device_name": device,
                "timestamp": datetime.now(timezone.utc).strftime("%Y-%m-%dT%H:%M:%S.%fZ"),
                "value": round(random.uniform(0, 100), 2),
            }
            client.publish(TOPIC, json.dumps(payload), qos=1)
            print(TOPIC, payload)
        time.sleep(5)
except KeyboardInterrupt:
    pass
finally:
    client.loop_stop()
    client.disconnect()
```

Sample message:

```json
{"device_name": "sensor-1", "timestamp": "2026-10-22T17:29:03.512339Z", "value": 42.17}
```

## Accepting Data in AnyLog

The policies below map the Python publisher's message into table `hivemq_sensor`. 
Use `!default_dbms` or replace it with your logical database name.

For the HiveMQ simulated telemetry, use the topic and keys captured with `mqtt-cli` above. Generic template:

```anylog
<run msg client where 
   broker = <HIVEMQ_IP> and 
   port = 1883 and 
   log = false and 
   topic = (
      name = <SIMULATED_TOPIC or TOPIC/#> and 
      dbms = !default_dbms and 
      table = "bring [<KEY_FOR_TABLE_NAME>]" and           # or a fixed name, e.g. hivemq_telemetry
      column.timestamp.timestamp = "bring [<TIMESTAMP_KEY>]" and   # or now()
      column.<col1> = (type = str and value = "bring [<KEY_1>]") and 
      column.<col2> = (type = float and value = "bring [<KEY_2>]")
   )
>
```

Replace `broker = <HIVEMQ_IP> and port = 1883` with `broker = local` when using Option B (MQTT).

### Option A – Subscribe directly to HiveMQ

AnyLog acts as an MQTT client of the HiveMQ broker.

```anylog
<run msg client where 
   broker = <HIVEMQ_IP> and 
   port = 1883 and 
   log = false and 
   topic = (
      name = sensors/data and 
      dbms = !default_dbms and 
      table = hivemq_sensor and 
      column.timestamp.timestamp = "bring [timestamp]" and 
      column.device_name = (type = str and value = "bring [device_name]") and 
      column.value = (type = float and value = "bring [value]")
   )
>
```

If HiveMQ authentication is enabled, add `user = <USER> and password = <PASSWORD>` to the `where` clause.

### Option B (MQTT) – HiveMQ forwards to AnyLog's local broker

1. Enable the message broker on the AnyLog node (skip if already running): 

```anylog
<run message broker where 
   external_ip = !external_ip and external_port = !anylog_broker_port and 
   internal_ip = !ip and internal_port = !anylog_broker_port and 
   bind = false and threads = 3
>
```

2. Configure the HiveMQ Enterprise Bridge Extension 
   (<a href="https://docs.hivemq.com/hivemq-bridge-extension/latest/index.html" target="_blank">docs</a>) to forward `sensors/#` to AnyLog. 
   Sample bridge configuration (verify element names against the extension version you deploy):

```xml
<hivemq-bridge-extension>
    <bridges>
        <bridge>
            <name>anylog</name>
            <remote-broker>
                <connection>
                    <static>
                        <host>ANYLOG_IP</host>
                        <port>ANYLOG_BROKER_PORT</port>
                    </static>
                </connection>
            </remote-broker>
            <topics>
                <topic>
                    <filter>sensors/#</filter>
                </topic>
            </topics>
        </bridge>
    </bridges>
</hivemq-bridge-extension>
```

3. Subscribe to the forwarded topic on AnyLog's local broker:

```anylog
<run msg client where 
   broker = local and 
   log = false and 
   topic = (
      name = sensors/data and 
      dbms = !default_dbms and 
      table = hivemq_sensor and 
      column.timestamp.timestamp = "bring [timestamp]" and 
      column.device_name = (type = str and value = "bring [device_name]") and 
      column.value = (type = float and value = "bring [value]")
   )
>
```

> If the bridge adds a prefix to forwarded topics, use the prefixed name (e.g. `hivemq/sensors/data`) in `name`.

### Option B (Kafka) – HiveMQ forwards to Kafka

The <a href="https://docs.hivemq.com/hivemq-kafka-extension/latest/index.html" target="_blank">HiveMQ Enterprise Extension for Kafka</a> 
writes MQTT messages from `sensors/#` into a Kafka topic (e.g. `hivemq-sensors`). The MQTT payload is forwarded 
as the Kafka record value, so the same JSON mapping applies.

> `run kafka consumer` connects to a Kafka cluster – point `ip` / `port` at the Kafka bootstrap server that 
> HiveMQ writes to.

```anylog
<run kafka consumer where 
   ip = <KAFKA_IP> and 
   port = 9092 and 
   reset = latest and 
   log = false and 
   topic = (
      name = hivemq-sensors and 
      dbms = !default_dbms and 
      table = hivemq_sensor and 
      column.timestamp.timestamp = "bring [timestamp]" and 
      column.device_name = (type = str and value = "bring [device_name]") and 
      column.value = (type = float and value = "bring [value]")
   )
>
```

## Validating

On the AnyLog node:

```anylog
get msg client                         # subscription status + message counters
get streaming                          # data being buffered for the table 
get operator                           # rows inserted (operator node)
```

Query the data:

```anylog
run client () sql !default_dbms format=table "select device_name, min(value), max(value), count(*) from hivemq_sensor group by device_name"
```
